# ComfyUI ワークフローの作り方 (アプリが値を入れる場所の目印)

PrismLab・PromptWordCrafter・ImageMimicArt・J-Rate から ComfyUI のワークフローを使うときに、
プロンプト・元画像・リファレンス画像・ラストフレーム・長さなどを**ワークフローのどこに入れるか**は、
ノードの種類と**タイトル**で決まります。この文書は、ワークフローを作る・直すときの手引きです。

- 決まりの元は `docs\generation-standard.md` の「5. ComfyUI とのやりとり」。中身は GenCommon の `gencommon\comfy.py` (Python の 3 アプリ) と J-Rate の `ComfyVideo.cs` にあります。
- 決まりを変えたときは、この文書と generation-standard の両方を直します。

## 1. 保存のしかた

- ComfyUI のメニュー **「Export (API)」** (Save (API Format)) で保存した JSON を登録します。ふつうの保存 (画面の形の JSON) は読めません。
- **タイトル**は、ノードを右クリック →「Title」で付けた名前です。API 形式の JSON では `_meta.title` に入ります。大文字・小文字は区別しません。
- タイトルや中身を直したら、もう一度「Export (API)」で保存し直します。

## 2. 早見表

| 入れるもの | ワークフローでの印 | 例 |
|---|---|---|
| プロンプト | 文字欄に `{prompt}` と書く (いちばん確実)。書かなければ下の「3.1」の順で探す | `{prompt}, cinematic lighting` |
| ネガティブ | タイトルに `Negative` を含むノードには、プロンプトを入れない | 「Negative Prompt」 |
| 元画像 (ファーストフレーム) | 使われている `Load Image` に入る。特別なタイトルは要らない | 「Load Image」「First Frame」 |
| リファレンス画像 (主に顔) | `Load Image` のタイトルに `reference` / `ref` / `face` / `参照` / `リファレンス` / `顔` | 「Face Reference」「顔」 |
| ラストフレーム | `Load Image` のタイトルに `last` / `end` / `final` / `ラスト` / `最後` / `終わり` / `終了` | 「Last Frame」「End Image」「ラストフレーム」 |
| 長さ (秒) | `Float` / `Int` ノード (PrimitiveFloat / PrimitiveInt) のタイトルに `duration` | 「duration」 |
| シード | 何もしなくてよい (`seed` / `noise_seed` は毎回ランダムになる) | — |
| 出力 | 保存のノード (Save Image / Save Video など) を置く | — |
| モデル・LoRA・サイズなどの値 (PrismLab だけ) | 何もしなくてよい。PrismLab の生成ステップの「値を変える」で、送るときに差し替える (3.11) | — |

## 3. それぞれの決まり

### 3.1 プロンプト

アプリが送る文 (読み取った文・盛った文・自分で書いた文に、ベースプロンプトを改行して付けたもの) を、次の順で探した場所に入れます。

1. **`{prompt}` の目印**: どのノードでも、文字欄に `{prompt}` と書いてあれば、その部分だけを置き換えます。前後に書いた語は残ります (例: `{prompt}, masterpiece` → `(送る文), masterpiece`)。目印が複数あれば、すべて置き換えます。
2. 目印がなければ、次のどちらかがあればそこ (すべて):
   - 文字列が直接入っている `prompt` という入力
   - 文字列ノード (`PrimitiveString` / `PrimitiveStringMultiline` など) で、タイトルに `Positive` か `User Prompt` を含むもの (ComfyUI のテンプレートの「Text (User Prompt)」など)
3. それもなければ `CLIP Text Encode` の `text`: 1 つだけならそれ、複数あるならタイトルに `Positive` を含むもの。

- タイトルに `Negative` を含むノードには、どの場合も入れません。
- 入れるのは**実際に使われる場所**だけです (下の「3.8」)。
- プロンプトを送らないとき (空のとき) は、ワークフローに書かれた文のまま実行します。`{prompt}` の目印だけは空にして送ります。
- 入れる場所が見つからない・使われていないときは、登録や生成のときに理由が出ます。迷ったら `{prompt}` を書くのがいちばん確実です。

### 3.2 元画像 (ファーストフレーム)

- **実際に使われる画像の入口すべて**に元画像を入れます。ただし、リファレンス画像・ラストフレーム・ラベルの画像を渡したときは、そのためのもの (下の 3.3・3.4・3.4b) は除きます。
- 画像の入口は `Load Image` のほか、**入力に画像の名前 (`.png` / `.jpg` / `.webp` など) が書かれているノード**です (Load Image (as Mask) やカスタムノードの読み込みも入ります。PrismLab・ImageMimicArt など GenCommon を使うアプリ。2026-11-26)。URL や `C:\...` のような絶対パスを読むノードは入口にしません。J-Rate はまだ `Load Image` だけです。
- ファーストフレームとラストフレームを指定するワークフローでも、ファーストフレーム用の `Load Image` には特別なタイトルは要りません (「First Frame」と付けても構いません)。
- PromptWordCrafter は元画像を送らないので、`Load Image` はワークフローに書かれた画像のまま使います。

### 3.3 リファレンス画像 (主に顔)

- タイトルに次の言葉を含む `Load Image` が、リファレンス用になります。
  - 英語 (単語として): `reference` / `ref` / `face`
  - 日本語: `参照` / `リファレンス` / `顔`
- 英語は**単語として**見ます。`Refine` や `Surface` などの一部には反応しません。`Face Reference`、`ref_image` (区切りが `_` でも可) は反応します。
- アプリがリファレンス画像を渡したときだけ、分けて入れます。渡さなければ、リファレンス用の `Load Image` にも元画像を入れます (今までどおり)。
- 使えるアプリ: PrismLab の物語 (シーンごとに「リファレンス (顔)」を選ぶ) と量産ライン (「画像」のステップで入れる先を「リファレンス」に。あとの生成すべてに使う)。量産ラインでは、`Load Image` がリファレンス用だけのワークフロー (T2I + 顔) も、前にその画像のステップがあればテキストの入口から使えます。J-Rate はまだ対応していません (すべての `Load Image` に元画像が入ります)。

### 3.4 ラストフレーム

ファーストフレームとラストフレームを指定する動画のワークフロー (FLF2V など) で使います。

- タイトルに次の言葉を含む `Load Image` が、ラストフレーム用になります。
  - 英語 (単語として): `last` / `end` / `final`
  - 日本語: `ラスト` / `最後` / `終わり` / `終了`
- 英語は**単語として**見ます。`Legend`・`Blender`・`Weekend` などには反応しません。`Last Frame`、`End Image`、`end_frame` は反応します。
- リファレンスの言葉も一緒に含むタイトル (例: `End Face`) は、**ラストフレーム**として扱います。
- アプリがラストフレームを渡したときだけ、分けて入れます。渡さなければ、ラストフレーム用の `Load Image` にも元画像を入れます。
- 使えるアプリ: PrismLab の物語 (シーンごとに「ラストフレーム」を選ぶ。手元の画像か、次のシーンの元画像) と量産ライン (「画像」のステップで入れる先を「ラストフレーム」に。2026-11-26)。PrismLab では、ラストフレーム用の `Load Image` があるのにラストフレームを決めていないと、候補を作らずに知らせます。J-Rate はまだ対応していません。

**例 (ファーストフレーム・ラストフレームのワークフロー)**

| ノード | タイトル | 入るもの |
|---|---|---|
| Load Image | First Frame (何でもよい) | 元画像 |
| Load Image | Last Frame | ラストフレーム |
| Load Image | Face Reference | リファレンス画像 (あれば) |
| Text (文字列) | Positive | プロンプト |
| Text (文字列) | Negative | 入れない |
| Float | duration | 長さ |

### 3.4b ラベルを決めた画像 (PrismLab の量産ライン)

リファレンス・ラストフレーム以外の画像 (スタイル・ポーズ・背景など) を、決めた入口に入れるときに使います (2026-11-26)。

- 画像の入口のタイトルを、レシピの「画像」のステップの入れる先「ラベル」と**同じ**にします (大文字・小文字は区別しません。一部だけでは合いません)。例: タイトル「Style」→ ラベル「Style」。
- ラベルの合うものは、リファレンス・ラストフレームの言葉より先に見ます (「Face Style」とラベルを決めれば、リファレンスではなくその画像が入ります)。
- ラベルの画像を決めていなければ、その入口にも元画像を入れます。

### 3.5 タイトルの付け方の注意

- `Load Image` のタイトルには、**入れたいもの以外の言葉を入れない**ようにします。例えば元画像用に「Background Reference」と付けるとリファレンス用に、「Start/End」と付けるとラストフレーム用になってしまいます。
- 迷ったときは、元画像用は「Load Image」や「First Frame」、リファレンス用は「Face Reference」、ラストフレーム用は「Last Frame」のように、はっきりした名前にします。

### 3.6 長さ (秒)

- タイトルに `duration` を含む `Float` / `Int` ノード (PrimitiveFloat / PrimitiveInt) の値に入れます。
- なければ、数値が直接入っている `duration` という入力に入れます。
- 端数がなければ整数で入れます。`Int` ノードなら、アプリの欄も整数だけになります。
- どちらもなければ、長さはワークフローに書かれたままです (アプリには「長さは変えられません」と出ます)。

### 3.7 シード

- 数値が直接入っている `seed` / `noise_seed` は、毎回ランダムにします。
- シードを固定したいときは、`Int` ノードなどから線でつなぎます。線でつながっている入力は触りません。

### 3.8 実際に使われるノード

- アプリが値を入れるのは、**実際に実行されるノード**だけです。保存のノードなど、どこにもつながっていないノードから線を逆にたどって届くものを「使われる」とみなします。
- **If/Else Switch** (`on_true` / `on_false` と `switch`): `switch` の値で使われない側はたどりません。`switch` が線でつながっていて決まらないときは、両方とも使われるとみなします。
- どこにもつながっていない `Load Image` や文字列ノードは、無視されます。

### 3.9 出力

- 動画が 1 つでも出れば、動画を 1 つ受け取ります (mp4 を優先)。なければ、出た画像をすべて受け取ります (保存用の出力があればそれ、なければプレビュー)。
- 受け取れる形式: 動画 `.mp4 .m4v .webm .mov .mkv .gif .webp`、画像 `.png .jpg .jpeg`。
- 保存のノードを置き忘れると、何も受け取れません。

### 3.10 ワークフローの種類 (アプリの色分け)

アプリは、ワークフローの中身から種類を自動で決めます。

- **画像から / 文字から**: 実際に使われる `Load Image` があれば画像から (I2○)、なければ文字から (T2○)。
- **動画 / 画像**: ノードの種類名に `video` を含むもの、または `SaveWEBM` / `SaveAnimatedWEBP` / `SaveAnimatedPNG` があれば動画 (○2V)。
- **I2I CN**: 画像から画像のうち、ControlNet (種類名に `controlnet` を含む、または `control` と `apply` を両方含むノード) を使うもの。
- 動画用か画像用かで、付けるベースプロンプトも変わります。

### 3.11 値を変える (PrismLab の生成ステップ。2026-11-25)

モデル・LoRA・サイズ (megapixels)・サンプラー・フォルダなど、**値だけが違うワークフローを何本も作らない**ための仕組みです。

- PrismLab のレシピの生成ステップで「値を変える」に足した値を、送るときにワークフローの中で差し替えます。**ワークフローのファイルは書き換えません**。
- 変えられるのは、実際に使われるノードの、値が直接入っている入力です (線でつながった入力は変えられません)。プロンプト・長さ・シード・`Load Image` の画像は、アプリが入れるので出しません。
- 場所はノードの番号と入力名で覚えます。ワークフローを ComfyUI で作り直してノードの番号や種類が変わると、その値は「場所がない」と赤で出て、量産を始められません。ステップの設定で選び直します。
- なので、値を変えて使うワークフローは、ノードを足し引きせずに値だけ直して保存し直すのが安全です。
- 1 本にまとめられないもの: つなぎ方が違うもの (画像の参照の仕方・LoRA の数・ControlNet の有無)、系統の違うモデル (CLIP や VAE も変わる)。これらは別のワークフローにします。

## 4. 確かめ方

- **「生成の設定」でワークフローを登録したとき**に、確認の結果が出ます (動画用か画像用か、プロンプトを入れる場所の数、長さを変えられるか、元画像を送るか)。
- **図の画面** (「図で設定」) では、プロンプトを入れる場所が「ノード 6「Positive」の text」のように出ます。
- **PrismLab の物語**では、選んだワークフローがリファレンス・ラストフレームに対応していなければ、その欄に「対応なし」と出ます (指を置くと、タイトルの付け方が出ます)。

## 5. アプリごとの違い

| | PrismLab | ImageMimicArt | PromptWordCrafter | J-Rate |
|---|---|---|---|---|
| プロンプト・長さ・シード | ○ | ○ | ○ | ○ |
| 元画像を送る | ○ | ○ | ✕ (ワークフローの画像のまま) | ○ |
| リファレンス画像 | ○ (物語・量産ライン) | ✕ (元画像が入る) | ✕ | ✕ (元画像が入る) |
| ラストフレーム | ○ (物語・量産ライン) | ✕ (元画像が入る) | ✕ | ✕ (元画像が入る) |
| ラベルの画像 | ○ (量産ライン) | ✕ (元画像が入る) | ✕ | ✕ (元画像が入る) |
