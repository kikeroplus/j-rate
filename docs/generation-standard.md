# AI 画像・動画生成の挙動の標準

ローカルの ComfyUI に画像を渡して、動画や画像を生成させる機能の決まりごとです。
J-Rate で使いながら固めたもので、今後つくる生成アプリはこの挙動を引き継ぎます。

- **基準実装**: J-Rate の `ComfyVideo.cs` (設定・ComfyUI とのやりとり)、`ComfyJobs.cs` (ジョブ一覧)、`JRate.cs` の「生成する (ComfyUI)」以降 (ジョブの管理と各ダイアログ)。
- ファイルの一覧・選択・評価などの操作は [ui-standard.md](ui-standard.md) に分けてある。
- J-Rate は「手元の画像を元に生成する」(i2v / i2i) アプリ。元画像のない生成 (t2i / t2v) を作るときは、5 章の「元画像」に関わる部分を読み替える。
- 末尾の「未確認の点」は、実際の ComfyUI での確認や利用者の判断がまだのもの。新しいアプリに持ち込む前に確かめる。
- **この決まりを持つアプリ**: J-Rate (i2v / i2i)、PromptWordCrafter (テキスト → t2i / t2v)、ImageMimicArt (画像 → 読み取り → t2i / i2i)。生成と読み取りの登録 (接続先・ワークフローなど) は 3 つで共有し、Python の 2 つは同じ部品を使う (11 章)。アプリごとに違う点は、その節に名前を挙げて書く。

---

## 1. 考え方

- **ワークフローは ComfyUI で作り、アプリは差し替えるだけ。** アプリが知っているのは「画像・プロンプト・長さ・シードをどこに入れるか」だけで、ノードの組み方には立ち入らない。
- **よく変えるものはプリセットにして、毎回の入力を減らす。** 接続先、ワークフロー、プロンプトは別々に登録し、組み合わせを「セット」で呼び出す。
- **生成は裏で進め、その間もアプリを普通に使える。** 進み具合と取り消しはジョブ一覧にまとめる。
- **どの設定で作ったかを残し、同じ設定でやり直せる。**

## 2. 登録するもの

| 種類 | 中身 | 件数 | 共有 (11 章) |
|---|---|---|---|
| 接続先 | 名前 + URL (既定 `http://127.0.0.1:8188`) | 10 | 3 つで共有 |
| ワークフロー | 名前 + JSON ファイルのパス | 100 | 3 つで共有 |
| ベースプロンプト | 動画用と画像用が 1 つずつ | 2 | 3 つで共有 |
| エンハンサー | 名前 + 指示文 + 送る文の雛形 + temperature (6 章) | 20 | 3 つで共有 |
| 読み取りプリセット | 名前 + 指示文 + 送る文 + temperature (6 章) | 20 | 3 つで共有 (使うのは J-Rate と ImageMimicArt) |
| LLM の接続 | サーバーURL、読み取り用モデル、エンハンサー用モデル、送る画像の大きさ | 1 | 3 つで共有 |
| プロンプト | 名前 + 本文 (改行あり) | 100 | J-Rate だけ (他の 2 つはプロンプトをファイルから取る) |
| セット | 名前 + 接続先・ワークフロー・プロンプト・長さ・読み取り・エンハンサー | 10 | アプリごと |

- 3 つのプリセット (接続先・ワークフロー・プロンプト) は互いに独立。ワークフローを接続先に結び付けない。
- 枠の数は固定で、空の枠は「(未登録)」と出す。一覧の表示は「番号 + 名前」(ワークフローはファイル名、プロンプトは本文の先頭も添える)。
- **セットは中身を値で覚える** (接続先は URL、ワークフローはパス、プロンプトは本文の写し)。プリセットの番号を入れ替えても、あとでプロンプトのプリセットを書き換えても、セットは変わらない。
- **セットの読み取りとエンハンサー**: 読み取りプリセットの名前 (「なし」も覚える) と「読み取り済みでも読み直す」のチェック、エンハンサーの名前 (「なし」も覚える)。読み取りのないアプリ (PromptWordCrafter) では読み取りを持たない。どちらも共有の登録で、アプリをまたいで中身を直すことがあるので、例外として名前で覚える。セットを選んだときは同じ名前のものを選び、登録になければ「なし」にしてステータスバーで知らせる (記録から「この設定で生成する...」と同じ扱い)。
- セットに項目がない (前の形式で保存したもの・その項目を持たないアプリで保存したもの) ときは、その欄は今のままにする (7 章の貼り付けと同じ)。
- ImageMimicArt はプロンプトを画像から作るので、セットにプロンプトを持たない (空で保存し、選んでもプロンプトの欄は変えない)。
- ワークフローは、ComfyUI の「Export (API)」で保存した JSON だけを受け付ける。普通の保存形式のときは、その旨を説明して断る。

## 3. 設定画面 (「生成の設定」)

- タブで分ける: 接続先 / ワークフロー / プロンプト / ベースプロンプト / セット。
- プリセットのタブは同じ作り: 枠を選ぶドロップダウン、名前、値、「プリセットを保存」「削除」「▲ 上へ」「▼ 下へ」。
  - 「プリセットを保存」はその場で書き込む (キャンセルしても残る)。
  - 枠を切り替えると、保存していない編集は捨てる。
  - 登録済みの枠の削除は確認する。
  - 上へ / 下へは隣と入れ替えてすぐ保存する。番号で覚えている参照 (使用中の接続先・ワークフロー、前回のプロンプトやセット) は入れ替えに合わせて直す。
- 接続先は「接続テスト」、ワークフローは読み込みの確認ができ、結果に「動画用 / 画像用」と、プロンプトや長さを変えられるかを出す。
- オプション (どちらも既定はオン)
  - 元の画像の評価を、生成したファイルに引き継ぐ
  - 生成が終わったら、出来たファイルを表示する
- **エクスポート / インポート**: すべての設定を 1 つの JSON にまとめて、別の PC へ持って行ける。
  - ワークフローの JSON は中身ごと入れる。インポート先に同じパスのファイルがなければ `%APPDATA%\(アプリ名)\workflows` に書き出し、登録してあるパスを付け替える。すでにあるファイルは上書きしない。
  - インポートは今の設定を**すべて置き換える** (混ぜない)。確認してから行い、直前の設定は自動で控えを残す (同じ形式なので、インポートし直せば戻せる)。
  - 生成の記録 (6 章) は含めない。
  - 共有の設定 (11 章) とそのアプリの設定を一緒に入れる。インポートでは、共有するファイルは共有の置き場所へ、それ以外はそのアプリへ書く (どちらのアプリでエクスポートしたものでも、共有する前の形式でも読める)。共有の設定は他の 2 つのアプリにも効くので、確認の文でそのことを伝える。

## 4. 生成の画面 (「生成する」)

生成のたびに必ず出す。上から順に次の欄を並べる。

1. **セット** — 選ぶと、その中身 (接続先・ワークフロー・プロンプト・長さ・読み取り・エンハンサー) を下の欄に入れる。「保存」(名前を聞く)「削除」。
2. **接続先**、**ワークフロー** — 登録済みのものから選ぶ。
3. **プロンプトのプリセット** — 選ぶとすぐ本文の欄に入れる。「保存」「削除」。
4. **プロンプト** — **Enter は改行。** 開始は「生成する」ボタンか **Ctrl+Enter** だけ。
   - その下に **読み取り** (なし / 読み取りプリセット) と「読み取り済みでも読み直す」(J-Rate と ImageMimicArt。6 章「読み取り」)、**エンハンサー** (なし / 登録済みのもの。3 つとも) を並べる。それぞれの横に「設定...」(読み取りの設定 / エンハンサーの設定を開く)。
5. **長さ (秒)** — 1〜60。**回数** — 1〜20 (同じ設定でシードだけ変えて繰り返す)。
6. 「コピー」「貼り付け」(7 章)、「生成の設定...」、「図で開く」、「生成する」「キャンセル」。

決まりごと。

- **開いたときは前回のまま。** 前回選んでいたセットとプロンプトのプリセットは選ばれた状態で出すが、欄の中身をそこから入れ直すことはしない (選んだあとに手で直した内容を消さない)。
- 前回の値として覚えるのは、**実際に生成を始めたとき**だけ。キャンセルしたら覚えない。
- ワークフローを変えたら、その場で欄を使えるかどうかを切り替える。プロンプトや長さを入れる場所がないワークフローでは、その欄を無効にする。読めないワークフローなら赤字で理由を出し、「生成する」を押せなくする。
- プロンプトの欄の下に、付け足されるベースプロンプトを薄い字で見せる (`＋ ベースプロンプト (動画用) : ...`)。
- 「生成の設定...」を押したら、入力中の内容を持ったまま設定を開き、閉じたら同じ内容で開き直す。設定を OK で閉じたときは、そこで選んだ接続先とワークフローを使う。

### 図の画面 (「図で開く」)

いつもの画面と同じ欄を、相関図 (GenCommon の `docs/relations-columns.html`) の並びに置き直した、もう 1 つの生成の画面。いつもの画面はそのまま残し、ボタンで行き来する。

- 「生成する」で開くのは**図の画面** (利用者の希望。2026-11-08)。図の画面の「いつもの画面で開く」でいつもの画面に、いつもの画面の「図で開く」で戻る。入力した内容 (接続先・ワークフロー・長さ・回数・セット・読み取り・読み直す・エンハンサー・ベースプロンプトのチェック) は持っていく。どちらで開いていたかは覚えない。
- **左** (ユーザーが設定する): 処理の段と同じ高さに、その段で使う設定を置く。上から「元にするもの (読み取りのあるアプリでは読み取りプリセット・読み直すも)」「(J-Rate だけ) 入力するプロンプト (プロンプトのプリセットも)」「エンハンサー」「ベースプロンプト」「ワークフロー (長さ)」「接続先 (回数)」。共有の設定は見出しに「(共有)」と付ける。セットは上の行。
- **真ん中** (処理、上から順に): 「読み取り / 本文」→ (J-Rate だけ)「組み立て」(入力 + 説明。`{caption}` の位置か、説明 + 改行 + 入力) →「エンハンサーで盛る」→「ベースプロンプトを付ける」→「ワークフローに入れる」→「ComfyUI で生成」。J-Rate の読み取りは「なし」も選べるので、そのときは読み取りの段も薄くする。選んだときだけ通る段 (読み取り・盛る・ベース) は点線の枠。通らない設定のとき (読み取り済み、エンハンサーなし、ベースを付けない) は題を薄くし、「なし (素通り)」などと出す。
- **右** (出力、送る前の確認): 真ん中の段をクリックすると、その段を通ったあとの内容を出す。開いたときは最後の段 (送るもの: 接続先・ワークフロー・長さ・回数と、送る本文)。
  - 生成を押す前なので LLM は呼ばない (「今読み取る」を押したときだけ呼ぶ。下の項)。まだ決まらない文は〈読み取った説明プロンプト〉「〈盛った本文〉＋」と書く。エンハンサーの段では、LLM に送る指示 (system) と送る文 (雛形の `{prompt}` を置き換えたもの) を出す。ワークフローの段では、本文を入れる場所 (ノードの番号・タイトル・入力名) を出す。
  - まとめて生成のときは 1 件目を例に出す。
  - 左で設定を変えたら、真ん中と右をすぐ直す。
- **「今読み取る」** (読み取りのあるアプリの、真ん中の「読み取り」の段の中の小さなボタン): 生成を待たずに、その場で LLM に読ませて .txt に書く。
  - 読み取るもの: 未読み取りの画像 (「読み取り済みでも読み直す」がオンならすべて)。すべて読み取り済みなら、ボタンは「今読み直す」になり、すべて読み直す。
  - 読み取りが「なし」のとき、画像がないとき (「図で設定」で画像を選んでいない) は押せない。
  - 裏で読み、段に「読み取り中... n / m」、終わったら「n / m 枚を今読み取りました」と出す。読み取っている最中は「生成する」を押せない (ジョブでも同じものを読み取ってしまうので)。
  - 読み終えたら、左の説明プロンプト・右の確認を読み取った文で出し直す。「読み直す」がオンだったら外す (今読み取ったので、生成のときは読み直さない)。そのまま生成すると、ジョブでは読み取らない。
  - 失敗したら、そこで止めて理由を出す (それまでに読み取ったものは .txt に書いてある)。画面を閉じても、読み終えたものは .txt に書く。
- 「生成する」の中身・覚える前回の値は、いつもの画面と同じ。
- **「図で設定」** (メインの画面の「生成の設定」の隣。PromptWordCrafter は生成のボタンの並び、ImageMimicArt はツールバー、J-Rate は右クリックメニューの「図で設定...」): 同じ図の画面を、生成せずに開く。ボタンは「設定を保存」で、選んだもの (接続先・ワークフロー・長さ・セット・読み取り・読み直す・エンハンサー・ベースプロンプトのチェック) を前回の値として保存し、次に「生成する」で開いたときにその設定で始まる。キャンセルなら保存しない。
  - 選択中 (なければ表示中) のファイルがあれば、その本文 (説明プロンプト) で送る前の確認を見せる。なければ〈本文〉〈読み取った説明プロンプト〉と書く。J-Rate では入力したプロンプトとプロンプトのプリセットも前回の値として保存する。本文が空でも保存できる (止めるのはワークフローを読めないときの赤字だけで、それでも保存はできる)。
  - 回数・「いつもの画面で開く」・コピー / 貼り付けは出さない。
- 今後 (案): 生成中のジョブがどの段にいるかを光らせ、済んだ段をクリックすると実際に送った内容を出す。

### ベースプロンプト

- 毎回のプロンプトのあとに、**改行をはさんで**付け足す固定の文 (画質の指定など)。
- 生成の画面の「＋ ベースプロンプト」の行はチェックボックスになっていて (3 つとも)、外すと付けずに送る (記録のベースプロンプトは空になる)。チェックの状態は前回の値として覚える (生成を始めたときだけ。「生成の設定...」から戻ったときもそのまま)。
- 動画用と画像用のどちらを使うかは、ワークフローから自動で決める: ノードの種類名に `video` を含むもの (大文字小文字は問わない)、または `SaveWEBM` / `SaveAnimatedWEBP` / `SaveAnimatedPNG` があれば動画用。それ以外は画像用。
- セットにも、パラメーターのコピーにも含めない。記録には別の項目として残す (やり直すときに二重に付かないように)。やり直すときは、その時点のベースプロンプトを使う。

## 5. ComfyUI とのやりとり

### 流れ

1. `POST /upload/image` — 元画像を送る。名前は英数字だけの一時的なものにする (日本語のファイル名で失敗しないように)。
2. ワークフローに値を入れる (下の表)。
3. `POST /prompt` — 実行を頼む。
4. `GET /history/{id}` を 2 秒おきに見て、終わるのを待つ。待っている間は `GET /queue` で順番を調べて「順番待ち」と出す。
5. `GET /view` — 出来たファイルを受け取って保存する。

### ワークフローのどこに入れるか

| 値 | 入れる場所 |
|---|---|
| 元画像 | すべての `LoadImage` ノードの `image` |
| プロンプト | 文字列に `{prompt}` の目印があれば、その部分を置き換える (ノードの種類・タイトルは問わない。前後の語は残す)。目印がなければ、文字列が直接入っている `prompt` 入力と、タイトルに `Positive` / `User Prompt` とある文字列ノード (`PrimitiveString*` の `value`。ComfyUI テンプレートの「Text (User Prompt)」) があればそこ (すべて)。なければ `CLIPTextEncode` の `text` — 1 つならそれ、複数ならタイトルに `Positive` とあるもの。タイトルに `Negative` とあるノードには入れない。どちらの場合も、実際に使われる場所だけに入れる (保存ノードなど、どこからも使われていないノードから線を逆にたどって届く場所。If/Else Switch は `switch` の値で使われない側をたどらない)。使われる場所が 1 つもなければ、理由と「`{prompt}` を書いて」と伝えて登録・生成させない (J-Rate のように元画像だけで生成できるアプリでは、入れる場所の候補がまったくないワークフロー (アップスケールなど) は許し、プロンプト欄を使えなくする。止めるのは、目印や候補はあるのにどれも使われないときだけ) |
| 長さ | タイトルに `duration` とある Float / Int ノードの `value`。なければ、数値が直接入っている `duration` 入力。端数がなければ整数で入れる |
| シード | 数値が直接入っている `seed` / `noise_seed` を毎回ランダムにする |

- 他のノードからつながっている入力 (`[ノード番号, 出力番号]` の形) は触らない。
- プロンプトや長さを指定しなかったときは、ワークフローに書かれている値のまま実行する (ただし `{prompt}` の目印は空にして送る)。

### 出力の受け取り

- 動画が 1 つでもあれば、動画を 1 つ (mp4 を優先)。なければ、出力された画像をすべて (保存用の出力があればそれ、なければプレビュー)。
- **元画像と同じフォルダに保存する。** 名前は `(元の名前)_video.(拡張子)` / `(元の名前)_i2i.(拡張子)`。同じ名前があれば ` (2)` ` (3)` を付け、上書きしない。
- そのフォルダを今開いていれば、一覧にすぐ加える。

### うまくいかないとき

- 接続できないときは「ComfyUI が起動しているか確認してください」と URL を添えて伝える。
- 待っている途中で応答がなくなっても (ComfyUI の再起動など)、1 分ほどは待ち続ける。
- エラーの文は日本語にし、ComfyUI が返した理由があれば添える。

## 6. ジョブ・記録・完了後の動き

### ジョブ

- 生成は 1 件ずつ「ジョブ」として登録する。複数を同時に頼める。
- 同じ接続先には**同時に 2 件まで**送り、残りはアプリ側で「待機中」にしておく。
- ジョブ一覧 (ツールバー「生成ジョブ (n)」/ Ctrl+J): 状態と進み具合を一覧し (処理する順に並べる。実行中の行は色付きの太字にし、一覧の上に「実行中: (ファイル名) (進み具合)」と待機の件数を常に出す。新しく実行に移った行が見えるようにスクロールする。完了したものは「時間」の列に生成にかかった時間を出す。ComfyUI の記録の execution_start〜execution_success、分からなければ実行に移してからの時間)、「一時停止 / 再開」(「一時停止」の節)「選択したものをキャンセル」「すべてキャンセル」「結果を表示」(ダブルクリックでも)「終わったものを消す」ができる。
- **キャンセル**: 待機中ならその場で取り消す。実行中なら ComfyUI の待ち行列から外し、ちょうど自分の番で動いているときだけ中断を送る (他のジョブを巻き添えにしない)。
- 1 件ずつの進み具合はステータスバーにも出す。複数が残っているときは「実行中 2 件・待機 5 件」を添える。

### まとめて生成

- 対象は 3 通り: 表示中の 1 枚 / 選択中の画像すべて / 一覧に表示中の画像すべて (右クリックメニュー)。動画は対象から外す。
- 生成の画面は 1 回だけ出し、画像 1 枚 × 回数ぶんのジョブを登録する。
- 合計が 30 件を超えるときは確認する。
- まとめて生成のときは、失敗してもダイアログを出さない (状態はジョブ一覧で見せる)。ジョブ一覧を自動で開く。

### 終わったとき

- 元の画像の評価を、出来たファイルに引き継ぐ (オプション)。見るのは**終わった時点**の評価 (生成中に付けた評価も引き継ぐ)。更新日時は変えない。
- 1 件だけの生成なら、出来たファイルへ移動して表示する (オプション)。まとめて生成のとき、複数選択しているとき、別の処理中、絞り込みで隠れているときは移動しない。
- すべてのジョブが終わったとき、アプリが手前にいなければ、タスクバーの点滅と音で知らせる。
- 生成中にアプリを閉じようとしたら「残して閉じる / 捨てて閉じる / やめる」を聞く (どちらで閉じても ComfyUI 側の実行は止まらない)。

### 続きから始める

PromptWordCrafter で入れ、3 つのアプリ共通にした決まり。

- 終わっていないジョブ (待機中・実行中) を、状態が変わるたびに `%APPDATA%\(アプリ名)\comfy_jobs.json` に書く。実行中のものは ComfyUI の `prompt_id` も残す。書きかけで落ちても壊れないよう、別名に書いてから置き換える。
- 送るプロンプトは登録した時点のものを残す (あとでテキストや設定を変えても、頼んだときの内容で続ける)。
- 「残して閉じる」で閉じたときや PC が落ちたときは、次に起動したときに「続きから始める / ジョブを中断」を聞く。Esc は「続きから始める」(うっかり捨てないように)。
- 続きから始める: 依頼済みのものは、ComfyUI の記録にあれば結果を受け取り、待ち行列にいればそのまま待つ。どちらにもなければ依頼し直す (seed は変わる)。待機中だったものは改めて依頼する。元のファイルが見つからないものは除き、件数を伝える。
- ジョブを中断: 残りを取り消し、依頼済みのものは ComfyUI の待ち行列から外す (つながらなければそのまま)。
- 生成の途中でも、待ち行列にも記録にもなくなったら (ComfyUI の再起動など) 依頼し直す (一時停止中を除く。次の節)。待ち行列を先に見てから記録を見る (その間に終わっても記録で拾える)。
- 同時に終わったジョブが同じファイル名を選ばないよう、名前を決めてから保存し終えるまでは 1 件ずつ行う。
- アプリは 2 重に起動しない (2 つ目は起動中のウィンドウを手前に出して終わる)。同じジョブを 2 つのアプリが取り合わないように。
  - J-Rate は 2 重起動を止めていない (利用者の判断。複数の J-Rate を開く使い方を残す)。代わりに、`comfy_jobs.lock` を開いている最初の J-Rate だけがジョブを書き、続きから始める。2 つ目以降の J-Rate は前のとおり、閉じると結果を受け取れない (閉じるときにそう伝える)。

### 一時停止

PromptWordCrafter で入れ、3 つのアプリ共通にした決まり。途中で止めてワークフローなどを直し、続きを生成する使い方のため。

- ジョブ一覧のボタンの先頭に「一時停止」を置く。一時停止中は「再開」に変わる。止める単位は待ち行列の全体だけ (1 件ずつは止めない)。
- 一時停止すると、新しく ComfyUI に依頼するのをやめる。ComfyUI に依頼済みのもの (実行中) は最後まで生成して受け取る (途中まで進んだ分を無駄にしない)。
- ワークフローの JSON は依頼する直前に読み直すので、一時停止中に直せば再開後のジョブから直した中身で生成する。
- 一時停止中の見せ方: 待機中の行の状態は「一時停止」。一覧の上には目立つ色 (オレンジ) で「一時停止中 (待機 n 件)」を出し、実行中のものが残っていれば「実行中のものが終わったら止まります」と添える。ツールバーは「生成ジョブ (n・一時停止中)」、ステータスバーには「[一時停止中]」を添える。
- 一時停止中に ComfyUI から消えた (再起動など) ものは、依頼し直さずに待機へ戻す。つながらない状態が 1 分ほど続いたものも、失敗にせず待機へ戻す (`prompt_id` は残し、再開したときにまだ残っていれば受け取る)。
- 一時停止中に新しく登録したジョブは待機に入れ、ジョブ一覧を開いて「再開で始まる」ことをステータスバーで伝える。
- 終わっていないジョブがなくなったら、一時停止は自動で解く (次に登録したものが黙って止まらないように)。
- 一時停止が止まりきっている (実行中がない) ときにアプリを閉じたら、何も聞かずにジョブを残す。実行中が残っていれば、今までどおり「残して閉じる / 捨てて閉じる / やめる」を聞く。
- `comfy_jobs.json` は `{"paused": true/false, "jobs": [...]}` の形で書く (前の、一覧だけの形も読む)。一時停止したまま閉じたときは、次に起動したときに何も聞かず、一時停止のまま一覧に戻す (依頼済みのものだけ、結果を受け取りにいく)。

### AI で盛ってから送る (エンハンサー)

PromptWordCrafter で入れ、3 つのアプリ共通にした決まり。

- エンハンサーは、ローカル LLM (LM Studio などの OpenAI 互換 API) に本文を書き足させるための登録。名前・指示文 (system)・送る文の雛形 (`{prompt}` が本文に置き換わる)・temperature を持つ。生成 AI のモデルごとに推奨の書き方が違うので、モデルごとに登録して選ぶ。
- 生成の画面のプロンプトの下に「エンハンサー」(なし / 登録済みのもの) を置く。前回選んだものを覚える (生成を始めたときだけ)。セットには名前で含める (2 章)。パラメーターのコピーには含めない。
- ジョブの番が来たら、ComfyUI に送る前に盛る (状態は「AI で盛っています...」)。ジョブごとに盛るので、回数を増やすと毎回違う盛り方になる。ベースプロンプトは盛らずに、盛った本文のあとに付ける。
- エンハンサーの中身 (指示文・接続先・モデル) は登録した時点の写しをジョブに持たせる。盛った本文もジョブに残し、続きから始めるときは盛り直さない。
- 盛れなかったらジョブの失敗にする (元の本文のまま黙って送らない)。盛っている間もキャンセルが効く。一時停止中に盛り終わったものは、盛った本文を持ったまま待機に戻す。
- 記録には元の本文 (`prompt`) に加えて `enhancer` (名前) と `enhancedPrompt` (盛った本文) を残す。「旧」の判定は元の本文で行う。「生成時の設定」で盛った本文を見せ、「この設定で生成する...」では同じ名前のエンハンサーを選んで盛り直す (登録になければ「なし」にして知らせる)。

### 読み取り (画像から説明プロンプトを作る)

ImageMimicArt で入れた決まり。J-Rate と ImageMimicArt が持つ (PromptWordCrafter は元画像がないので持たない)。

- 元画像をビジョン対応のローカル LLM (OpenAI 互換 API の `/v1/chat/completions`) に見せて、説明プロンプトを書かせる。画像は `image_url` に `data:image/jpeg;base64,...` で渡す。
- 送る前に縮める: 長い辺を「送る画像の大きさ」(既定 1024px、256〜4096) にし、JPEG で送る。元より大きくはしない。透過は白で埋める。
- **読み取りプリセット**: 名前・指示文 (system)・送る文 (user)・temperature。20 個。登録・並べ替えはエンハンサーと同じ作り (その場で保存)。初めて使うときは例を 2 つ入れておく (自然文の詳しい説明 / タグ)。
- 「読み取りの設定」: LLM のサーバーURL・読み取り用のモデル (「モデル取得」「接続テスト」)・送る画像の大きさ・読み取りプリセット。サーバーURL はエンハンサー (と PromptWordCrafter の翻訳) と同じものを使う。モデルは読み取り用とエンハンサー用を別に選ぶ。
- ビジョン非対応のモデルが画像を受け付けなかったときは、その旨と「読み取りの設定」でモデルを替えることを日本語で伝える。
- 返事の全体を囲むコードブロック・引用符・`<think>...</think>` は取り除く (エンハンサーと同じ)。空ならジョブの失敗にする。

**説明プロンプトのファイル**

- 元画像と同じフォルダに、拡張子を除いた名前の `.txt` (`photo.png` → `photo.txt`) を UTF-8 で書く (学習用キャプションと同じ慣習)。読み込むときは PromptWordCrafter と同じ順で文字コードを判定する (utf-8-sig → utf-8 → cp932 → utf-16 → latin-1)。
- `.txt` があれば読み取り済みとみなし、自動では読み直さない。画像を選んだだけでは読み取らない。
- `photo.png` と `photo.jpg` が並んでいると同じ `.txt` を使う。読み取るときにこの重なりがあれば、ステータスバーで知らせる。
- 画像を削除・コピー・移動するときの `.txt` の扱いはアプリで違う:
  - **J-Rate と ImageMimicArt**: 一緒に動かす。コピーでは `.txt` もコピーし、移動では一緒に移す。削除では一緒にごみ箱へ送る。ただし同じ名前の別の画像 (`photo.png` に対する `photo.jpg`) が元のフォルダに残るときは、`.txt` は残す (移動ではコピーにする)。行き先に同じ名前の `.txt` があれば、画像と同じ付け方 (` (2)` など) にそろえる。
  - ImageMimicArt にはコピー・移動がないので削除だけ。ほかのアプリで画像だけ消されて残った `.txt` は「説明だけ残っている .txt を整理」で片付ける (ImageMimicArt の仕様)。

**生成での使い方**

- 生成の画面の「読み取り」でプリセットを選ぶと、ジョブの中で使う。未読み取りの画像だけ読み取り、「読み取り済みでも読み直す」がオンなら読み直して `.txt` を上書きする。前回の値として覚える (生成を始めたときだけ)。
- 送るプロンプトの組み立て:
  - **ImageMimicArt**: 説明プロンプトをそのままプロンプトにする (プロンプトの欄は説明を見せるだけ。ImageMimicArt の仕様)。
  - **J-Rate**: 入力したプロンプト (動きの指示など) に説明を足す。入力に `{caption}` の目印があればそこを説明に置き換え (いくつあってもすべて)、なければ「説明 + 改行 + 入力」にする。入力が空なら説明だけ。読み取りが「なし」なら今までどおり入力だけを送る (`{caption}` の目印は空にする)。
  - この組み立てたものをエンハンサーに渡し、最後にベースプロンプトを付ける (ワークフローの `{prompt}` の目印とは別のもの)。
- J-Rate の生成の画面では、プロンプトの欄の下に `＋ 説明プロンプト: (先頭の部分)` / `＋ 説明プロンプト: まだ読み取っていません (ジョブの中で読み取ります)` を薄い字で出す (ベースプロンプトの行と同じ見せ方)。まとめて生成のときは「読み取り済み a 枚 / 未読み取り b 枚」。
- ジョブの中の順番: **読み取り** (状態「読み取っています...」) → **盛る** (「AI で盛っています...」) → **ComfyUI**。
  - 同じ画像の複数のジョブ (回数 2 以上) は、最初の 1 件だけが読み取り、残りはそれを待って同じ説明を使う。
  - どの段で失敗してもジョブの失敗にする。どの段でもキャンセルが効く。読み取った説明と盛った本文はジョブに残し、続きから始めるときに済んだ段はやり直さない。
  - 一時停止は ComfyUI に頼む手前で止める (読み取り・盛りが済んだものは、その結果を持ったまま待機に戻す)。
  - 読み取りプリセットの中身 (指示文・接続先・モデル・送る画像の大きさ) は、登録した時点の写しをジョブに持たせる。
- 1 枚で未読み取りでも、生成の画面ではその場で読み取らない (待たせない)。ジョブの中で読み取る。

**手で読み取る・直す**

- ImageMimicArt: 右の「説明プロンプト」の枠 (ImageMimicArt の仕様)。
- J-Rate: 右クリック「説明プロンプト...」(画像のときだけ) で小窓を開く。中身を見る・直す (Ctrl+S で保存)・「読み取る」(Ctrl+R。`.txt` があれば「読み直す」になり、上書きを確認する)。読み取り中は小窓を閉じても裏で続け、終わったら `.txt` に書いてステータスバーで知らせる。

**記録** には `reader` (読み取りプリセットの名前) と `caption` (送った時点の説明の写し) を足す。J-Rate の `prompt` は入力したもの (組み立てる前)。「この設定で生成する...」は同じ名前の読み取りプリセットを選び、説明は今の `.txt` を使う (読み直さない)。

### 記録

- 出来たファイル 1 つにつき 1 件: 元の画像、日時、接続先、ワークフロー、プロンプト、ベースプロンプト、長さ (エンハンサーを使ったときは、その名前と盛った本文も)。
- 置き場所は PC ごとに 1 つのファイル (`%APPDATA%\(アプリ名)\comfy_history.txt`、1 行に 1 件の JSON)。写真のフォルダには何も置かない。
- 探すときはまずフルパスで、なければファイル名で探す (生成後に別のフォルダへ移したものも見つかる)。新しい記録を優先する。
- 右クリックメニュー「生成時の設定...」(記録があるときだけ有効) で内容を見せ、「この設定で生成する...」で元の画像に対して同じ内容を入れた生成の画面を開く。
- PromptWordCrafter では、出来たファイル (生成結果のサムネール) の右クリックにも「生成時の設定...」があり、そのファイルを作ったときの記録を見せる (記録のないものでは無効)。
- PromptWordCrafter には大きく見るメイン表示がないので、生成結果のサムネールをクリック (修飾キーなし・ドラッグでないとき) すると、一覧の上の空いた場所に小窓で大きく出す (画面に収まる大きさ。元より大きくはしない。下に名前と元の大きさ)。小窓はフォーカスを取らず、キーは一覧のまま効く: ← → で切り替え (小窓の上のホイールでも)、Del で消すと次を表示、Esc で閉じる。同じものをもう一度クリック、一覧の空き・小窓・他の場所のクリック、アプリから離れたときも閉じる。ダブルクリック / Enter は関連付けアプリで開く (小窓は閉じる)。

## 7. パラメーターのコピー / 貼り付け

- 生成の画面の「コピー」「貼り付け」と、生成時の設定の「パラメーターをコピー」。
- クリップボードには**人が読める文章**で入れる。1 行目が目印 `[J-Rate 生成パラメーター]`、続いて「接続先 / URL / ワークフロー / ワークフローのパス / 長さ」の行、`プロンプト:` の次の行から最後までがプロンプト。
- 貼り付けでは、登録済みの接続先とワークフローを選ぶ (ワークフローは、パスが違ってもファイル名が同じなら合わせる)。登録にないものは、何がないかを伝える。
- 長さやプロンプトの行がなければ、その欄は今のままにする。回数は含めない。

## 8. 設定ファイル

共有するものは `%APPDATA%\GenCommon\`、アプリごとのものは `%APPDATA%\(アプリ名)\` に置く (11 章)。ファイルの名前と形式はどちらも同じ。

**共有 (`%APPDATA%\GenCommon\`)**

| ファイル | 内容 |
|---|---|
| `comfy_presets.txt` | 接続先 (1 行に「番号 Tab 名前 Tab URL」) |
| `comfy_workflows.txt` | ワークフロー (同じ形) |
| `comfy_base_prompt_video.txt` / `_image.txt` | ベースプロンプト |
| `enhancer_presets.json` | エンハンサー (JSON の配列。1 件は `name` / `system` / `template` / `temperature`) |
| `reader_presets.json` | 読み取りプリセット (同じ形) |
| `llm_url.txt` / `reader_model.txt` / `enhance_model.txt` / `reader_max_side.txt` | LLM のサーバーURL / 読み取り用モデル / エンハンサー用モデル / 送る画像の大きさ |
| `apps.txt` | 共有を使っているアプリの設定フォルダ (1 行に 1 つ。番号の入れ替えを伝えるため) |

**アプリごと (`%APPDATA%\(アプリ名)\`)**

| ファイル | 内容 |
|---|---|
| `comfy_preset.txt` / `comfy_workflow_preset.txt` | 使用中の接続先 / ワークフローの番号 |
| `comfy_prompt_names.txt` / `comfy_prompt_1.txt`〜`_100.txt` | プロンプトの名前 / 本文 (1 件 1 ファイル。J-Rate だけ) |
| `comfy_sets.txt` | セット (JSON。読み取りは `reader` (名前、空 = なし) と `reread` (true / false)、エンハンサーは `enhancer` (名前、空 = なし)) |
| `comfy_prompt.txt` / `comfy_seconds.txt` | 前回のプロンプトと長さ |
| `comfy_set.txt` / `comfy_prompt_preset.txt` | 前回選んだセットとプロンプトのプリセット |
| `comfy_use_base_prompt.txt` / `comfy_inherit.txt` / `comfy_jump.txt` | ベースプロンプトを付けるか / 評価の引き継ぎ / 完了後に表示 |
| `enhancer_generate.txt` / `reader_generate.txt` / `reader_reread.txt` | 生成の画面で前回選んだエンハンサー / 読み取りプリセットの番号 (0 = なし) / 「読み直す」 |
| `comfy_history.txt` / `comfy_jobs.json` | 生成の記録 / 終わっていないジョブ |
| `gencommon_merged.txt` | 共有に移した印 (11 章) |

- 前回選んだもの・使用中の番号・オプションは、アプリごとに使い方が違う (i2v と t2i ではワークフローも違う) のでアプリごとに持つ。
- 記録とジョブは共有しない (2 重起動を防ぐのはアプリごとなので、ジョブを共有すると取り合いになる)。
- 形式を変えるときは、古いファイルを読んで引き継ぐ (たとえばプリセットができる前の単一の設定は、1 番の枠に入れる)。

## 9. 画面と文言

- 動詞は「生成する」。設定は「生成の設定」、進み具合は「生成ジョブ」、記録は「生成時の設定」。
- ツールバーの並び: 生成する | 生成ジョブ | 生成の設定。
- 右クリックメニューの並び: 生成する / 表示中の画像をまとめて生成する (N 枚)... / 説明プロンプト... (読み取りのあるアプリ) / 生成時の設定... / 生成ジョブの一覧... / 生成の設定... / 読み取りの設定... (読み取りのあるアプリ) / エンハンサーの設定...
- 使えないときはボタンやメニューを無効にする (動画を表示中は「生成する」を押せない、など)。

- 生成まわりは、開発中は偽の ComfyUI サーバーでしか確かめていない部分がある (i2i の出力名、まとめて生成とキャンセル、同時 2 件の制限、評価の引き継ぎ、完了後の移動)。
- 今後: 複数の J-Rate から同じジョブ一覧にジョブを足せるようにしたい (利用者の希望。今は最初の J-Rate だけがジョブを残せる)。
- 作った側の判断で決めたままの点:
  - ワークフローを接続先に結び付けていない
  - プロンプトのプリセットを選ぶと、入力途中のプロンプトを上書きする
  - 生成の記録を PC ごとに持つ (写真のフォルダに置かない)
  - 動画用 / 画像用の自動判定に、手動の切り替えがない
  - インポートは置き換えのみ (混ぜる方法がない)
  - WebP の静止画は一覧に出ない

## 11. 3 つのアプリで共有するもの

J-Rate・PromptWordCrafter・ImageMimicArt は、生成と読み取りの登録を共有し、同じ決まりで動く。

### 共有の置き場所

- `%APPDATA%\GenCommon\` に、8 章の「共有」のファイルを置く。どのアプリで登録・変更しても、ほかの 2 つにそのまま効く。
- セット・前回の値・使用中の番号・オプション・記録・ジョブはアプリごと (8 章)。

### 初めて共有するとき (引き継ぎ)

- アプリを起動したとき、そのアプリの設定フォルダに `gencommon_merged.txt` がなければ、一度だけ自分の設定を共有に移す。
  - 共有にまだそのファイルがなければ、自分のものをそのまま写す。
  - 共有にすでにあれば、共有にないもの (接続先は URL、ワークフローはパス、エンハンサーと読み取りプリセットは名前と中身が同じものを同じとみなす) を空いている枠に足す。入りきらなかったものは件数を知らせる。
  - ベースプロンプトと LLM の接続は、共有が空のときだけ自分のものを入れる。違っていれば共有のほうを残し、そのことを知らせる。
  - 使用中の番号・前回選んだ番号は、移したあとの位置に付け替える。
  - アプリの古いファイルは消さない (戻したいときのため。共有に移したあとは読まない)。
  - 移したもの・足したものはステータスバーで知らせる。
- PromptWordCrafter の LLM の接続 (`promptwordcrafter_settings.json` の `translate_url` と `enhance_model`) は、`llm_url.txt` と `enhance_model.txt` に移す。翻訳のモデル (`translate_model`) は PromptWordCrafter のものとして残す。
- ImageMimicArt の「初めて起動したときに PromptWordCrafter の設定を写す」はこの仕組みに置き換える。

### 同時に使うとき

- 3 つのアプリを同時に起動していてもよい。
- プリセットの「保存」「削除」「上へ / 下へ」は、ファイルを読み直してから、その枠だけを変えて書く (別のアプリで足したものを消さない)。書くときは別名に書いてから置き換える。
- 設定の画面と生成の画面は、開くたびに共有のファイルを読み直す。
- 上へ / 下へで番号を入れ替えたときは、`apps.txt` にあるすべてのアプリの使用中・前回の番号を入れ替えに合わせて直す (各アプリは起動したときに自分の設定フォルダを `apps.txt` に書く)。セットとジョブは値で覚えているので影響しない。

### 共通の部品

- PromptWordCrafter と ImageMimicArt (Python) は、生成と読み取りの部品を `C:\Users\ilove\Desktop\WindowsApp\GenCommon\` の `gencommon` パッケージで共有する (設定と共有の置き場所、ComfyUI とのやりとり、ワークフローの書き換え、ジョブ、記録、エンハンサー、読み取り、LLM、各ダイアログ)。直すときはここを 1 回直せば両方に効く。アプリに残すのは、プロンプトの取り方・出力の置き場所と名前・結果の結び付けなど、アプリの役割で違う部分だけ。
- J-Rate (C#) は言語が違うので部品は共有できない。この文書と共有のファイルの形式で合わせる。

### アプリごとに違うところ (まとめ)

| | J-Rate | PromptWordCrafter | ImageMimicArt |
|---|---|---|---|
| プロンプトの元 | 生成の画面で入力 (+ 説明プロンプト) | テキストファイルの本文 | 説明プロンプト (`.txt`) |
| 元画像を ComfyUI に渡す | いつも | 渡さない | ワークフローに `LoadImage` があれば |
| 出力の置き場所と名前 | 元画像と同じフォルダ、`_video` / `_i2i` | テキストと同じフォルダ、`_t2i` / `_video` | 出力フォルダの下、`_mimic` |
| 読み取り | あり (生成の画面・説明プロンプトの小窓) | なし | あり (右の枠・生成の画面) |
| プロンプトのプリセット | あり | なし | なし |
| 画像の削除・コピー・移動での `.txt` | 一緒に動かす | (対象外) | 一緒に動かす (削除だけ) |
